# Existing accepted controller channels — 11 November 2026

This records interface provenance from existing owner-operated emulator/controller connections. It is not rights approval, complete feature acceptance or a proof that every offered field is necessary.

## Read-only collection

Protect reports 7.4.96. Existing local health endpoints and this project's own deployed source were read through the existing trusted NAS connection. No vendor backend source or firmware was read. No adoption, token generation, credential rotation, model task, media access, setting change or restart was initiated.

## Derivation checks

The selected deployed AI Key functions and their checkout counterparts were parsed by the same local Python AST parser and compared equal. Raw AST dump digests from different Python versions are not compared, because optional AST fields can differ. This replaces the earlier overly broad source-mismatch assumption for these selected functions, not for entire modules.

The selected AI Port receive/hello/reply functions compare equal. Its deployed connect loop differs in the control-enable condition (adopted control versus the newer explicit control gate). The fixed header/route construction was separately reviewed unchanged. No equivalence is claimed for the whole module.

The Key is adopted and connected, with positive validated incoming-command counters. The Port is adopted and connected with websocket_101 and positive hello/parameter-agreement counts. These are server interaction evidence, not merely headers generated offline.

The Key uses the device-service profile: it offers ucp4 but accepts an absent selected subprotocol. This record does not turn that into a negotiated-ucp4 claim. Its stable reconnect has no management token, so x-token remains unsupported by this record.
