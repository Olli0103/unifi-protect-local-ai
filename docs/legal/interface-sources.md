tls.py implements locally generated RSA/X.509 identity and independently pinned SHA-256 controller trust with standard cryptography APIs; these are local design choices, not claims about vendor-generated certificates or keys. No device firmware was consulted. General interoperability acceptance remains bounded by the referenced live reconnect records.

Local configuration keys, defensive size limits and standard TLS/HTTP choices are not automatically manufacturer facts. Tests do not recognize every future semantic protocol change; contributors must extend the reviewed inventory.

## Maintainer observation procedure

Run only against one device you own, after reviewing the tool:

```sh
python tools/discovery_observe.py --ip OWNED_DEVICE_IPV4
```

The CLI sends exactly one unicast `01 00 00 00` UDP request to port 10001 and waits at most three seconds for its reply. It outputs only the discovery header and TLV type/length metadata. No response values, addresses, MACs, hostnames or raw datagrams are printed or saved. It does not scan, broadcast or access a controller by itself.

A camera reply proves only that camera/version's shape. The tool cannot verify sysid values, byte order, multicast behavior, AI Key/AI Port-specific fields or firmware rights. Record only safe derived conclusions in a dated live record; do not publish raw responses. For other facts, use the per-row instructions and the corresponding parser of your own Protect installation. Never inspect AI Key/AI Port firmware to fill a gap.

Do not run broad automated diagnostics or change pairings/policies as part of this PR. Unobservable facts are candidates for a separately reviewed, positively and negatively tested removal, not permission to silently break working interoperability.
